# ADR-016: Read-only Sdk classes for system-managed resources

## Status

Accepted

## Context

The NoviCloud API documentation (`NoviCloud-REST-API-SDK-Notes.md`) explicitly marks several resources as GET-only — they are maintained by the NoviCloud system and cannot be created, modified, or deleted via the API:

| Resource | Reason |
|---|---|
| Kasy | Created and managed by POS hardware registration |
| Kasjerzy | Managed in NoviCloud back-office, not via REST |
| Dokumenty | Sales documents generated by POS, read-only via API |
| Pozdok | Document line items, generated with documents |
| Sprzedaz | Sales transaction records, generated by POS |
| RapSprzed | Aggregated report, generated on-the-fly |
| RapPracy | Cashier work time report, generated on-the-fly |

## Decision

SDK classes for the above resources expose only read operations:

- `listPage(XxxQuery)` — single page with pagination metadata
- `listAll(XxxQuery)` — auto-paginated `Iterable<T>`
- `count(XxxQuery)` — total record count
- `getById(Long)` — single record by ID (where the endpoint exists)

No `create`, `update`, `delete`, or Draft classes are created for these resources.

`RapSprzedSdk` and `RapPracySdk` do not expose `getById` because the `/rapsprzed/{id}` and `/rappracy/{id}` endpoints do not exist in the OpenAPI spec — reports are collection-only.

## Consequences

- SDK surface accurately reflects API capabilities.
- No misleading methods that would fail at runtime with `405 Method Not Allowed`.
- If a future API version adds write support for any of these resources, a Draft class and CUD methods must be added and a new ADR written.
