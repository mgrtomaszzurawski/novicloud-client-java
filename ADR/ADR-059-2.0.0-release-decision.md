# ADR-059: Promote 1.1.0 to 2.0.0 - interface/impl split for all *Client types

**Date:** 2026-05-03
**Status:** Accepted

## Context

The branch originally tagged for `1.1.0` accumulated three categories of
change across rounds 1-4 of Codex re-review:

1. **Behavioural fixes** (F-01..F-14): null-safe `getById`, POST retry
   default flipped, neutral exception mapping, unknown-enum tolerance,
   nested record fields, `Retry-After` honoured exactly. Closed in
   ADR-057.
2. **Internal-leak hiding** (CF-01..CF-04): `RetryHandler` and
   `LinkUtils` moved to `sdk.internal.*`; `NoviCloudException.of(String,
   ApiException)` rewritten to take a neutral `(String, Throwable, int,
   HttpHeaders, String)` so the public API no longer references the
   generated `ApiException` type. Closed in ADR-058.
3. **`*Client` constructor visibility** (F-02 / CF-02): all 18 `*Client`
   public constructors take the generated `ApiClient` and are reachable
   from the classpath, letting consumers bypass the `NoviCloudClient`
   facade and observe internal types. Marked `@Deprecated(forRemoval =
   true)` in 1.1.0 with the intent of removing them in 2.0.0.

Round 5 review (Codex `cf-rereview-round5-*.md`) correctly flagged that
items 2 and 3 above are **source-incompatible** changes. Under Semantic
Versioning a minor release must be backwards compatible at the source
and binary level for public API; relocating `sdk.RetryHandler` to
`sdk.internal.RetryHandler`, removing `LinkUtils` from `sdk.model`, and
changing the signature of a public static factory all break that
contract. Shipping these as `1.1.0` would have violated SemVer.

The user's decision was explicit and twofold:

> "zrobmy wersje 2.0 trudno. prawda jest taka ze nikt nie uzywa versji 1.0
> wiec bez roznicy mi czy bysmy zlamali semVer, ale jedzmy tak jak ksiazki
> pisza."

> "robimy wszystko, 2.0 wynikl tylko z semVer. wiec poprawiamy wszystko i
> wydajemy wersje 2.0"

In other words: bump to 2.0.0 to comply with SemVer, and since we are
already paying the major-version cost, do the full clean cut on
`*Client` access (interface + non-exported impl) rather than leaving the
deprecated public constructors in place.

## Decision

### Bump to 2.0.0 with no separate 1.1.0 release

`pom.xml` version is `2.0.0`. SCM `tag` is `v2.0.0`. There is no
`1.1.0` artifact and there will not be one - the 1.0.0 -> 2.0.0 jump
encompasses every fix accumulated on this branch.

### `*Client` types become interfaces; impls hidden

Every one of the 18 `*Client` types is now an `interface` in
`sdk.resources.<endpoint>`:

```java
package io.github.mgrtomaszzurawski.novicloud.sdk.resources.towary;

public interface TowaryClient {
    PagedResult<Towar> list(TowarQueryBuilder query);
    int count(TowarQueryBuilder query);
    Towar getById(Long id);
    String create(TowarCreateBuilder builder);
    void update(TowarUpdateBuilder builder);
    void deleteById(Long id);
}
```

The implementation lives in the non-exported package
`sdk.internal.resources.<endpoint>` as `<Endpoint>ClientImpl`:

```java
package io.github.mgrtomaszzurawski.novicloud.sdk.internal.resources.towary;

public final class TowaryClientImpl implements TowaryClient { ... }
```

`module-info.java` exports `sdk.resources.*` (the interfaces and
builders) and does **not** export `sdk.internal.resources.*`. JPMS users
therefore cannot reach the impls; classpath users can name the impls
but the constructors take an `ApiClient` and `RetryPolicy` and there is
no documented path to construct one outside the facade.

`NoviCloudClient` instantiates impls and exposes them through the
existing accessors (`client.towary()`, `client.asorty()`, ...) returning
the interface types.

### Removals (breaking)

The following public types/members from 1.0.0 no longer exist:

- `io.github.mgrtomaszzurawski.novicloud.sdk.RetryHandler` -> moved to
  `sdk.internal.RetryHandler`.
- `io.github.mgrtomaszzurawski.novicloud.sdk.model.LinkUtils` -> moved to
  `sdk.internal.mapper.LinkUtils`.
- `*Client` public constructors (e.g.
  `new TowaryClient(ApiClient, String, RetryPolicy)`) - the type is now
  an interface; impls are not in an exported package.
- `NoviCloudException.of(String, ApiException)` -> replaced by
  `of(String, Throwable, int, HttpHeaders, String)`. (Justified in
  ADR-058.)
- All record `from(XRaw)` factories (e.g. `Towar.from(TowarRaw)`) -
  records are pure data classes; mapping moved to
  `sdk.internal.mapper.RawMappers`. (Justified in ADR-057.)

### Migration

For the recommended usage pattern (`NoviCloudClient.builder().build(...)`
and `client.<endpoint>()` accessors) **no source changes** are needed
between 1.0.0 and 2.0.0. The pre-existing public surface of the facade
is unchanged. Breaking changes are limited to consumers that:

- Imported `sdk.RetryHandler` directly.
- Imported `sdk.model.LinkUtils` directly.
- Instantiated `*Client` types via their public constructor.
- Called `Record.from(RawType)` factories on SDK records.
- Constructed `NoviCloudException` via the old static factory.

Each path has a documented replacement (see the [2.0.0] migration block
in CHANGELOG.md).

### 1.0.0 deprecation on Maven Central

Once 2.0.0 is published the 1.0.0 coordinate stays on Central (Sonatype
does not allow deletion of released artifacts). To signal "do not use
1.0.0" we publish a follow-up `1.0.1` "relocation" POM whose only
contents are a `<distributionManagement>/<relocation>` element pointing
to `2.0.0`. Tools like Maven and Gradle surface a relocation warning
when consumers resolve the old coordinate. Tracked as a post-release
task; not part of the 2.0.0 artifact itself.

## Consequences

**Positive:**

- Public API surface in 2.0.0 contains zero generated types
  (`ApiException`, `Link`, `*Raw`). All consumer-visible types live in
  `sdk.*` (excluding `sdk.internal.*`).
- Constructing a `*Client` outside the facade is now genuinely
  impossible from JPMS modules and strongly discouraged for classpath
  consumers (they would need to name a class in `sdk.internal.resources`,
  which the README and CHANGELOG explicitly mark as private).
- SemVer compliance lets future Codex / Sonar reports reason about
  breakage classes correctly: any future move-to-internal can be a minor
  release as long as it stays inside `sdk.internal.*`.

**Negative:**

- Major version bump after one weekend of 1.0.0 in the wild. The user
  accepted this trade-off explicitly ("nikt nie uzywa wersji 1.0 wiec
  bez roznicy mi czy bysmy zlamali SemVer, ale jedzmy tak jak ksiazki
  pisza"); the principled reading is that 2.0.0 is the correct call
  even if no consumer is actively affected.
- Five extra files per endpoint (interface, impl, deprecation javadoc
  in the interface, two new test imports). Net code volume rose by
  ~3000 lines. The win is that the impl files are now genuinely
  private; the interface files are pure contract and tend not to
  change.
- The 1.0.0 -> 2.0.0 migration guide must enumerate every removed type
  rather than rely on `@Deprecated(forRemoval = true)` warnings during a
  1.x -> 1.x compile. Documented in CHANGELOG.md and
  `package-info.java`.
